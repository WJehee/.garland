= LibreWolf + KeePassXC browser integration

The KeePassXC browser extension talks to KeePassXC through a native messaging host: a manifest in `~/.librewolf/native-messaging-hosts` that tells LibreWolf which program (`keepassxc-proxy`) to start.
KeePassXC can write that manifest itself, but only knows the Firefox location (`~/.mozilla`), which used to require a manual symlink and a custom location in the KeePassXC settings.

This is now declarative:

* `modules/workstation/librewolf.nix` sets `programs.librewolf.nativeMessagingHosts = [ pkgs.keepassxc ]`, so home-manager links the manifest shipped by the keepassxc package into `~/.librewolf/native-messaging-hosts`.
* `modules/workstation/keepassxc.nix` switches off *Use a custom Browser Configuration Location* in KeePassXC on every activation, since the manifest is a read-only link into the nix store.

The only setting left to the KeePassXC UI is *Browser Integration* > *Enable browser integration*, plus connecting the extension to the database once.

== Migrating a machine that used the manual setup

The old setup left a symlink behind that home-manager refuses to overwrite ("existing file would be clobbered").
Remove it once, before rebuilding:

[source,shell]
----
rm ~/.librewolf/native-messaging-hosts
just rebuild
----

Then restart KeePassXC and LibreWolf.

== Checking that it works

[source,shell]
----
cat ~/.librewolf/native-messaging-hosts/org.keepassxc.keepassxc_browser.json
----

The file must be a link into `/nix/store` and its `path` must point at an existing `keepassxc-proxy`.
