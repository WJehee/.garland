= Garland

This repository contains all my NixOS configurations.

== Configurations

All my configurations are named after poisonous plants, not because I am toxic, but because I think they are cool.

* **Foxglove**: my Framework laptop
* **Wisteria**: my desktop workstation
* **Oleander**: my dedicated desktop PC, running as a homelab server (LLMs, Immich, Gitea)
* **Hemlock**: my VPS machine
* **Ivy**: Home Assistant running on a Raspberry PI
* **Wormwood**: AdGuard Home, the network DNS filter, running on a Raspberry PI

A few hosts are stubs: they import only the base module and have no role yet, so they evaluate but are not installed anywhere.

* **Manchineel**
* **Belladonna**

== Structure

This repository follows the https://github.com/mightyiam/dendritic[dendritic pattern]: every Nix file under `modules/` is a flake-parts module, discovered automatically with https://github.com/vic/import-tree[import-tree] (files prefixed with an underscore are skipped). Feature modules write into the `flake.modules.nixos.<name>` and `flake.modules.homeManager.<name>` namespaces, and each host (`modules/hosts/<name>`) composes the features it wants by importing them. `modules/nixos-configurations.nix` turns every `hosts/<name>` module into a `nixosConfiguration`.

== Private modules (wreath)

Some modules I want reproducible but not public live in a separate private repo, https://github.com/WJehee/.wreath[wreath].
It follows the same dendritic pattern and exposes its module tree as `flakeModules.default`, which this flake imports as the `wreath` input.
Because both trees write into the same `flake.modules.*` namespaces, a host imports a private feature (e.g. `nixos.hacking`) exactly like a public one.

`just rebuild` runs `nix flake update wreath` first, so every rebuild pulls the latest pushed wreath. To iterate on private modules without pushing, use `just rebuild-wreath`, which overrides the input with a local `../.wreath` checkout.

== Remote hosts

Servers are installed once with https://github.com/nix-community/nixos-anywhere[nixos-anywhere] and updated afterwards with https://github.com/serokell/deploy-rs[deploy-rs]:

[source,bash]
----
just remote-install <host> <user@address>   # first install, partitions the disk
just deploy <host>                          # every update after that
----

`just deploy` builds the configuration, copies the closure to the host, activates it and rolls back automatically if activation fails or the host becomes unreachable. It runs `nix flake check` first, which evaluates every host configuration, so a broken config anywhere stops the deploy.

All remote hosts are declared in one place, `modules/deploy.nix`. An entry gives the node its address and an explicit `remoteBuild`: build on the host itself, or build locally and copy the closure (the default for small VPSes). The login user, the target user and the doas command are shared by all nodes and set once at the top level.

The same declaration feeds the SSH client config: every deploy node becomes a `Host <name>` alias with its address and user on all machines, so `ssh hemlock` works wherever this configuration is installed and never disagrees with the deploy target.

=== Adding a remote host

1. Add the host module under `modules/hosts/<name>` as usual and install it with `just remote-install`.
2. Add an entry to `hosts` in `modules/deploy.nix` with its address and `remoteBuild` choice.
3. Rebuild your workstation to pick up the SSH alias, then `just deploy <name>`.

=== When a deploy goes wrong

The escape hatches, all passed after `--` to `just deploy`:

* `--boot` copies the closure and activates it on the next reboot.
* `--dry-activate` copies and tests the closure without switching.
* `--magic-rollback false` / `--auto-rollback false` disable the automatic rollback.
* `--skip-checks` skips the `nix flake check` step.

The manual fallback always works: ssh in and run `just r` in a checkout of this repository.

== Secrets management

Secrets are managed with https://github.com/Mic92/sops-nix[sops-nix]. Encrypted secrets are stored in `secrets/<hostname>.yaml` and decrypted at NixOS activation time using the host's SSH ed25519 key.

=== First-time setup

Export the age private key from the SSH host key (once per machine):

[source,bash]
----
mkdir -p ~/.config/sops/age
sudo nix run nixpkgs#ssh-to-age -- -private-key -i /etc/ssh/ssh_host_ed25519_key > ~/.config/sops/age/keys.txt
----

=== Editing secrets

[source,bash]
----
just secrets <hostname>
----

This opens the decrypted file in your editor. On save, sops re-encrypts automatically.

=== Adding a new host

1. Get the age public key from the host's SSH key:
+
[source,bash]
----
# From the host itself:
cat /etc/ssh/ssh_host_ed25519_key.pub | nix run nixpkgs#ssh-to-age

# Or remotely:
ssh-keyscan -t ed25519 <host> | nix run nixpkgs#ssh-to-age
----

2. Add the key to `.sops.yaml` under `keys:` with an anchor (e.g. `&hostname`), and add a `creation_rules` entry for `secrets/<hostname>.yaml`

3. Create the encrypted secrets file:
+
[source,bash]
----
just secrets <hostname>
----
